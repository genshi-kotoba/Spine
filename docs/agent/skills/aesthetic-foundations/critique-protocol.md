# 评审协议 — 给定一张图 / 一个页面, 按这 7 步走

不是 checklist 走完打钩 — 是**问问题的顺序**. 顺序错了会先陷入像素细节, 错过大问题.

---

## 1. 三秒第一印象

合上嘴, 先看 3 秒, 然后用一句中文描述:

- **眼睛先落在哪儿?** 哪个元素的视觉权重最强 (大小 × 对比 × 位置 × 色彩饱和度)?
- 那是**作者想让你先看的地方吗**? 还是个意外的焦点 (大 logo / 抢色 CTA / 错位元素)?

**failure mode**: 看到的第一个东西是 "页眉的版本号" / "右下角的步骤指示器" — 视觉权重错配.

---

## 2. 眯眼测试 (Squint Test)

字面意义眯起眼, 让所有细节糊掉, 只剩**亮度块 + 颜色块**:

- 还能分出"主块 / 次块 / 装饰"三层吗?
- 还是糊成一团均匀灰?

参考 photographers.md 的 Avedon — 他的肖像眯眼之后只剩"白底 + 一个黑色形状", 极致简化, 强迫看主体. 好 UI 同理.

**修复方向**: 如果一片均匀, 拉大主元素 (尺寸 / 字重 / 饱和度), 或弱化次要元素 (字号缩 / 颜色降级到 ink3).

---

## 3. 灰度测试 (Value Check)

在脑子里 / 实际工具里把所有颜色转成黑白:

- 层级还成立吗?
- 还是"全靠颜色撑着"?

**重要**: 颜色是装饰, **明度 (value) 是骨架**. Albers 的色彩交互核心论点之一 — 同样色相, 明度不同, 信息量天差地别.
如果灰度后看不出层级, 说明你在用色相代替明度做层级 (一个 #4CAF50 + 一个 #2196F3, 同饱和同明度 — 灰度后一样亮).

**判别**:
- ✅ 标题深 ink, 正文中 ink2, 元数据浅 ink3 → 灰度后清晰
- ❌ 标题红色, CTA 蓝色, 普通文字黑色 → 灰度后红蓝一样深, 全乱

---

## 4. 留白测试 (Negative Space)

留白有两种 — **意味的空** vs **没填满的空**.

问:
- 这片空白如果消失 (元素填进去), 信息会更清还是更糊?
- 空白是否在帮主元素"呼吸 / 被孤立 / 被强调"?
- 还是它只是"这里没东西放, 暂时空着"?

参考 ma-and-negative-space.md. 八大山人画一条鱼, 整张纸 90% 是空 — 那是**张力**, 不是空缺. Apple keynote 的极大留白也是这个套路.

**修复方向**: 把"暂时空着"的区域要么填进有用信息, 要么扩大并使其成为视觉构图的一部分 (比如让标题区域整体下沉, 上方大块留白 → 仪式感).

---

## 5. 裁剪测试 (Crop Test)

如果这是张照片要交给主编, 他会从哪四条边砍掉多少?

字面: 假装把图 / 页面边缘裁掉 10%, 再裁 20%, 看哪些元素消失后**主信息变强**:

- 边缘那个状态指示器, 没它信息更聚焦?
- 那个 "上次更新时间", 顶部还需要吗?
- 大段说明文字, 砍掉一半还能不能传达?

参考 Sargent (painters.md) — "what to leave out" 是他最高造诣. 设计师常忘记**减法是创作**.

**典型砍法**:
- 重复信息只留最强一处
- 装饰元素 (分隔线, badge, 图标) 砍 50% 以上
- 二级 / 三级 metadata 折叠到 hover / 详情页

---

## 6. 大师参照 (Master Comparison)

针对当前的视觉问题, 调出 2-3 个相关大师, 问"他们会怎么处理这个矛盾":

| 矛盾 | 调谁 |
|---|---|
| 信息密集 vs 留白 | Vignelli (网格密但克制) vs 原研哉 (空) — 看项目语境 |
| 色彩取舍 | Rothko (色块情绪) / Albers (色对比) / Saul Leiter (低饱和环境色) |
| 主体强调 | Avedon (隔离) / Vermeer (单光源) / Hopper (孤立框定) |
| 中文 / 东方 | 八大山人 (极简张力) / 倪瓒 (萧疏) / 宋瓷 (单色深度) |
| 工业 / 功能 | Rams 10 诫 |

参 [masters/](masters/) 各文件.

**用法**: 不是要复制大师风格 — 是**借他们的判断力**. "Vermeer 在这种构图会让光从哪边来?" "Rams 会保留这个装饰边框吗?"

---

## 7. 改动清单 (Concrete Moves)

输出**3-5 条具体可执行**的动作, 每条:
- 描述要改的元素 (定位)
- 描述动作 (减弱 / 加强 / 移位 / 删除)
- 描述预期效果 (为什么会更好)

**模板**:

```
1. [元素] 当前 [状态] → 改为 [状态]
   理由: [审美原则 + 期望效果]
```

**反例 (太抽象)**:
- ❌ "再干净一点"
- ❌ "提高对比度"
- ❌ "改进层级"

**正例**:
- ✅ "卡片底部的版本号 + 时间戳, 当前两条平排; 改为只保留时间戳, 版本号移到 ··· 菜单内. 理由: 时间是用户每分钟在意的, 版本号是排查时才看的, 把二者权重区分. (裁剪测试)"
- ✅ "整页只有一个 CTA 用 primary 色, 其余都 default. 当前两个按钮抢眼, 灰度后一样亮 → 没层级. 理由: 一页一个主行动 (Rams 第 4 诫 — 产品应该自解释, 不需要装饰式按钮)."

---

## 失败模式 (别落入)

- **跳到 token**: 协议第 7 步才允许说像素值; 1-6 步只说设计判断, 不说 "把 padding 改成 16"
- **找借口**: "我们的设计系统就这样" — 设计系统是工具不是免罪. 系统不够用就改系统.
- **过度引经据典**: 用大师名字必须配上**该项目场景下的判断**, 不要变成名词堆砌
- **忽略整体看局部**: 永远先看整页 / 整张图, 再看组件 / 局部
- **审美洁癖**: 不是所有页面都要极简. 一个"操作工具页"信息密就是它的美 (Vignelli 地铁图密但清晰)
