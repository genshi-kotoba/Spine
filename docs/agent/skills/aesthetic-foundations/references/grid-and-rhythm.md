# 网格与节奏 — 视觉的拍子

网格是一种克制 — 把"乱放"换成"有理由地放".
节奏是一种音乐 — 同一种间距在画面里**重复出现**, 形成视觉拍子.

---

## 1. 网格简史

- **15 世纪**: 古登堡圣经已经有黄金比例的页边距系统
- **包豪斯 (1920s)**: 工业网格作为美学
- **瑞士设计 (1950s-60s)**: Josef Müller-Brockmann, Karl Gerstner — 网格系统化, 成为现代平面设计基础
- **数字时代**: 12 列 (Bootstrap), 8 列, 4 列 — Web 网格简化版
- **当代**: 网格仍是骨架, 但允许"破格" (breaking the grid) 制造焦点

---

## 2. Müller-Brockmann 的核心论点

*Grid Systems in Graphic Design* (1981):

1. **网格是工具, 不是目的** — 是为了让设计师**做决策更快、更一致**, 不是炫技
2. **网格越约束, 创造力越被释放** — 不用每次纠结"放哪", 精力转去想"放什么"
3. **专业 vs 业余的区别在于看不见网格** — 业余把网格做出来 (生硬), 专业用网格让画面呼吸

**应用**: 设计稿如果"看起来很整齐但很僵", 多半是网格过于显眼. 修法: 允许少数元素**有意地** spans 跨网格.

---

## 3. 列网格 (Column Grid)

最常见网格: 把页面分成 N 列, 元素吃 1 到 N 列.

**常见列数**:
- **12 列**: 灵活, 6/4/3/2 都能整除 → web 默认
- **8 列**: 简洁, 适合工具型 / 数据型页面
- **6 列**: 杂志 / 长文页面
- **4 列**: 极简 landing / 海报

**Gutter (列间距)**: 通常 16-24px, 不要太宽 (糊不成网格了) 也不要太窄 (列粘在一起).

---

## 4. 基线网格 (Baseline Grid)

文字的水平参考线, 类似谱表上的横线 — 让多列文字的行**互相对齐**.

- 基线间距 = 正文行高 (例: 24px)
- 所有标题、副标题、正文行**贴齐**到 24px 倍数
- 标题字号大, 行高 1.2 → 标题占 2 个基线 (48px)

**应用**: 长文 / 杂志型 layout 一定要基线对齐. 工具 UI 可以放松点.

---

## 5. 8pt 网格 (8-point Grid)

数字 UI 常用约定: 所有间距都是 8 的倍数 (8 / 16 / 24 / 32 / 40 / 48 / 64).

**为什么 8**:
- 易整除 (大多屏幕分辨率是 8 的倍数)
- 视觉跳跃恰好 (4 太密, 16 太疏)
- 4pt 子网格 (tight UI): 4 / 8 / 12 / 16... 给密集表格用

**法则**:
- padding / margin / gap 都用 8 倍数
- 字号阶梯不必, 但行高最好 8 倍数 (16 / 24 / 32...)

**反例**: padding 13px, gap 17px, margin 9px → 看起来"差不多齐" 但实际乱.

---

## 6. 模块化阶梯 (Modular Scale)

间距 / 字号都遵循同一个**比例**, 形成数学和谐.

例: φ ≈ 1.618 阶梯起始 16:
- 16 → 26 → 42 → 68 → 110

例: 1.25 (major third) 阶梯起始 16:
- 16 → 20 → 25 → 31 → 39

**优点**: 任何两个尺寸**都和谐**, 因为它们共享同一个比例.
**实操**: 选定一个 base (通常正文 14-16px) 和一个 ratio (1.25 / 1.333 / 1.5 / 1.618), 生成所有字号 + 间距.

---

## 7. 节奏 (Visual Rhythm)

节奏 = 间距在画面里的**重复模式**.

**好节奏的特征**:
- 同级别元素之间间距**完全相同** (列表项之间, 卡片之间)
- 不同级别之间间距**清晰不同** (区块之间是 32, 区块内项之间是 12)
- 间距值**来自有限集合** (4 / 8 / 12 / 16 / 24 / 32 / 48 — 不出现 17, 27)

**坏节奏**:
- 第一个区块和第二个之间 24px, 第二个和第三个之间 28px → 视觉抖
- 卡片内左 padding 16, 右 padding 14 → 不对齐
- 间距集合有 12 种不同值 → 没节奏感

---

## 8. 双间距系统 (Density vs Comfort)

工具 UI 常需要两个 spacing 阶梯:

**Comfortable (信息稀, 阅读型)**:
- 4 / 8 / 16 / 24 / 32 / 48 / 64

**Dense (信息密, 操作型)**:
- 2 / 4 / 8 / 12 / 16 / 24 / 32

Notion, Linear, GitHub 都同时用两套.

---

## 9. 破格 (Breaking the Grid)

网格的目的是稳定, 破格的目的是惊喜. 偶尔有一个元素**跨越网格** = 焦点.

- 杂志: 大照片横跨双页, 跨过 gutter
- Landing: 主标语跨越 layout, 让网格"承载不住"它的气场
- UI: 一个 hero 卡跨 3 列, 其他卡 1 列

**关键**: 只能破 1 个地方. 全篇破 = 没网格 = 乱.

---

## 10. 不同语境的网格选择

| 项目类型 | 网格 |
|---|---|
| 工具 / dashboard | 12 列 + 4pt 子网格, 信息密集 |
| 文章 / 文学 / 长文 | 6-8 列 + 基线网格, 文字优先 |
| Landing / 营销 | 12 列, 允许跨列 hero, 多用破格 |
| 移动端 | 4-6 列, gutter 缩小 (12-16) |
| 海报 / 单页视觉 | 自由网格 + 黄金比例 / 斐波那契 |

---

## 11. 跨域映射 (绘画/摄影 → UI 网格)

- **绘画的对角线分割** (静物画里常见的对角动势线) → UI 的对角焦点 (左上 logo, 右下 CTA)
- **摄影的三分线** → web hero 主体放在右三分线交点, 文字配在左空间
- **建筑的柱距 / 模数** (Le Corbusier 的 Modulor) → UI 的 8pt 网格本质是同样思路

---

## 12. 反审美陷阱

- **网格无视**: 元素位置看心情, 没列对齐 — 业余感最重的一种.
- **网格过密**: 24 列 / 4 列子格 — 用户看不见, 你也不会真用全, 砍到 12.
- **间距值满地飞**: 13, 17, 23, 29 — 视觉抖. 修法: 限制到 6-8 个值的集合.
- **完美居中所有元素**: 列内 + 行内全居中 → 没有视觉锚点, 看哪都行 = 看不下去. 用左对齐做锚点, 居中留给少数仪式元素 (logo, 主标语).
- **基线漂移**: 多列文章, 左栏文字和右栏文字行高位置不一致 — 杂志感失败. 用 baseline grid 对齐.
