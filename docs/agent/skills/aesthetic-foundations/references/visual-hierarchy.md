# 视觉层级 — 让眼睛知道先看哪儿

视觉层级 = "信息重要程度"翻译成"视觉权重梯度".
一个好的画面 / UI / 海报, 用户**不假思索就知道阅读顺序**.

---

## 1. Gestalt 法则 — 眼睛的默认逻辑

格式塔心理学 (1910s 德国) 发现的人脑视觉默认规则. 设计是顺势, 不是逆势.

### 1.1 接近性 (Proximity)

**靠得近的东西被视为一组**.

应用:
- 标签和它对应的输入框靠近 (4-8px), 远离别的字段组 (24-32px)
- 一个卡片内的标题 + 副标题 间距 4-6px, 卡片之间间距 16-24px → 一眼分清"哪些是一组"

反例: 表单字段间距全部 16px → 不知道哪些是同组.

### 1.2 相似性 (Similarity)

**长得像的被视为一类**.

应用:
- 所有可点击元素用同一种视觉标记 (颜色 / 下划线 / 鼠标手型)
- 警告类用同一颜色家族 (warn-50 / warn-100 / warn-500)

反例: 链接有的蓝有的下划线有的箭头 → 用户每次都得猜.

### 1.3 闭合 (Closure)

**眼睛会自动补全不完整的形状**.

应用:
- 虚线框 / 间断分隔, 大脑自动看成完整框
- icon 设计常用 (一个开口的圆仍被识别为圆)

### 1.4 连续性 (Continuity)

**眼睛沿着平滑线移动**, 即使中间被打断.

应用:
- 一列数据沿垂直线对齐, 视觉自动连成一条
- 引导线 (leading line) 利用此原理

反例: 数据列没对齐, 数字左缘锯齿 → 视觉断裂.

### 1.5 共同命运 (Common Fate)

**朝同一方向运动 / 变化的元素被视为一组**.

应用 (静态): 朝同一方向倾斜的元素 (一组斜线 logo)
应用 (动态): 同时进出动画的卡片 = 一组.

### 1.6 图与底 (Figure-Ground)

**眼睛把画面分成"主体 (figure)" 和 "背景 (ground)"**.

应用:
- 主体要够清晰, 背景要够安静 (不要彩色背景 + 彩色主体)
- 反转可玩出招 (Rubin 杯 / 脸)

参 [composition.md §5 正负空间](composition.md).

## 2. 三层级法则

**法则**: 一个画面 / 页面 **最多 3 个视觉层级**.

- **L1 (主)**: 整个画面最先看到的, 一个
- **L2 (次)**: 第二批看到的, 3-5 个
- **L3 (补)**: 装饰 / metadata / 详情, 不限数量

**反例**: 4 个层级 = "标题 / 副标题 / 副副标题 / 正文 / 注释" — 用户分不清.

**判别**: 眯眼看, 能数出 2-3 层不同灰度 = 成立. 一片均匀 = 全平 = 失败.

## 3. 强调的工具箱

要"把这件事变重要", 有以下手段, **从最有效到最次**:

| 手段 | 强度 | 副作用 |
|---|---|---|
| 加大尺寸 (字号 / 占地) | ★★★★★ | 占空间 |
| 加重 / 加粗 | ★★★★ | 几乎无 |
| 加饱和色 (在中性背景上) | ★★★★ | 滥用 → 廉价 |
| 增加白空间 (孤立) | ★★★★ | 占空间, 但是最高级的强调 |
| 提高明度对比 (深底亮字 / 亮底深字) | ★★★ | 几乎无 |
| 反白 / 背景色块 | ★★★ | 占视觉权重 |
| 下划线 / 边框 | ★★ | 易俗 |
| 加图标 | ★★ | 易抢戏 |
| 动画 | ★★★★★ | 极强但慎用, 频繁动 = 烦 |

**Apple keynote 的招**: 一张图一个字 + **巨大留白** — 用白空间做强调, 极致.

## 4. 阅读路径 (Reading Path)

人眼在画面上是有路径的, **设计阅读顺序** 是核心.

参 [composition.md §3 视觉路径](composition.md).

UI 典型路径:
- 左上 logo / 主标
- 横向扫到右上 (CTA / nav)
- 向下到 hero 主体
- 继续向下到次级信息
- 最底层级 footer

任何想被注意的元素**逆这条路径放** = 失败. 顺势 = 容易看到.

---

## 5. 焦点 (Focal Point)

每个画面应该有**一个明确焦点**, 它就是"L1 主层级".

焦点制造手段:
- 最大 / 最强 / 最孤立
- 周围元素的视线 / 引导线指向它
- 颜色 / 明度上跳出
- 位置在阅读路径起点附近 (左上) 或交点 (三分线交点)

**坏焦点**: 没有 (用户不知道看哪), 太多 (3+ 元素争抢), 错放 (重要内容在右下角)

---

## 6. 留白即层级 (White Space as Hierarchy)

**留白的多少表达重要度**:
- 周围留白多 = 这件事重要, 单独存在
- 周围挤满 = 这件事不重要 / 是"列表项之一"

**典型应用**:
- Hero 区主标语周围**大量留白** (上下 100px+)
- 列表项之间**紧凑** (12-16px)
- 同一节区内, 标题和它的内容之间**适度留白** (16-24px), 不同节区之间**大留白** (48-64px)

---

## 7. 弱化也是工具

只想强化主体? 弱化所有别的.

- 把次要文字降级到 ink3 (从主黑变浅灰)
- 把装饰元素移除 (分隔线 / icon)
- 把次要按钮从 primary 改成 default 或 text-only
- 把次要数据藏到 hover / 详情页

设计师常忘: **强化等同于弱化对照组**. 想让 A 跳出来, 不是把 A 加粗加大, 而是把 B/C/D 全部弱化.

---

## 8. 一页一个主行动 (One Page, One CTA)

工业设计师 Dieter Rams 第 4 诫: 让产品自我解释. UI 等同: **每个页面只有一个"应该点的按钮"**.

- 多个 primary 按钮 → 用户选择疲劳
- "刷新" / "Sync Now" / "新建 rollout" 全部 primary → 实际"最重要的"是哪个?
- 通常: 一页一个 primary, 1-2 个 default, 其余 text-only / icon-only

**例外**: 工具页 (Photoshop / Figma) — 工具栏所有按钮平权, 因为没有"主任务", 全是可选.

---

## 9. 层级失败的常见信号

- 眯眼看, 一片均匀灰
- 用户问"我先看哪儿" / "下一步点哪儿"
- 用户截图给你, 关注到了错的元素
- 灰度后所有元素亮度相似
- 三层以上明显层级 (老板加了 "副副副标题")

---

## 10. 反审美陷阱

- **所有元素都强调** = 没有强调. 修法: 选 1 个 L1, 其余降级.
- **用颜色代替层级**: 红黄蓝标题各种色, 但同字号 — 灰度后全平.
- **居中堆叠**: 所有元素垂直居中, 缺锚点. 用左对齐建立纵向轴.
- **平等列表 + 一个特殊**: 9 个等权重卡片 + 1 个突然加粗 — 反而显得突出过头. 要么所有同等, 要么分组层级.
- **页面太满**: 每个角落塞东西 → 没"L0 背景空间" = 没层级 = 灾难. 修法: 删一半.
- **小图标 + 小文字 + 小 badge**: 全弱化 = 全无层级. 修法: 选一个升级.
